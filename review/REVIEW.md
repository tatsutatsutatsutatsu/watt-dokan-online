# エンジョイモード実装レビュー

## 変更点要約

- ルーム作成・ソロ開始時に「🎮 エンジョイモード」「⚔ ガチモード」を選べるUIを追加した。既定値と不正値のフォールバックはガチモード。
- 対人ルームでは作成者の選択を `room.mode` に保存し、参加者が送る値には依存しない。スナップショット・再接続・再戦でも同じモードを維持する。
- エンジョイモード限定で、HPが10以下の領域へ入った瞬間に「非常用電源」を発動する。プレイヤー・CPU・対人両席を同じ処理で判定する。
- 効果は「現在電力を最大電力以内で300W回復」または「通常の手札上限を適用して1枚ドロー」からランダムに1つ。
- 通常のゲームイベントに `emergencies` を同梱し、全画面カットイン・効果名・発動者・専用電子音をクライアントで再生する。
- 対戦画面と結果オーバーレイへ現在モードを常時表示する。
- エンジョイ戦も既存の総勝敗・試合数へ記録する一方、月間ランキング用の `rankedWin` / `rankedLoss` / `rankedGames` には加算しない。

## 「10以下ゾーンに入った瞬間」の判定

ゲーム状態に席ごとのラッチ `G.emergencyLow = { A:false, B:false }` を持たせた。各アクション解決後（死亡・ラストワード処理後）に `checkEmergency` を既存の共通処理経路から呼び出す。

- HPが11以上ならラッチを `false` に戻し、次回の進入を待つ。
- HPが10以下でラッチが `false` のときだけ `true` にして進入を検出する。
- エンジョイモードなら救済効果を1回発動する（致死ダメージで0以下へ入った場合も「10以下への進入」として通知するが、勝敗判定は従来どおり行う）。
- HPが10以下に留まる間はラッチが `true` のため再発動しない。
- 11以上へ回復するとラッチが解除され、再度10以下へ変化したときにもう一度発動できる。
- ガチモードでもラッチ自体はHP帯に同期するが、効果・イベント・ログは一切発生しない。

この方式により、ターン経過ではなくHP帯の境界通過だけを検出し、新しい効果解決経路は追加していない。

## 設計判断

- HP変更箇所を個別改修せず、既存 `applyAction` の効果・死亡解決後に全席をまとめて確認することで、攻撃、スペル、ファンファーレ、ラストワード、疲労などの経路を共通化した。
- 通知は新しいWebSocketメッセージ種別ではなく既存イベントへ配列を追加し、既存のスナップショット／イベント順序を維持した。
- ランキング除外のため総戦績を上書きせず、ランキング専用カウンタを併設した。旧データは「導入前は全試合がガチ」とみなして初回更新時に移行する。
- チュートリアルは従来ルールを変えないためガチモード固定とした。

## 既知の課題

- 効果選択は意図どおりランダムのため、手動確認で両効果を連続して再現するには複数回の試行が必要。自動テストでは乱数注入で両分岐を固定して検証している。
- 既存の保存済み戦績にはモード情報がないため、移行時は全件をランキング対象だったものとして扱う。
